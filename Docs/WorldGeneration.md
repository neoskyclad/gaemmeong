# 월드 생성

구현 순서와 역할 분담은 [월드 생성기 구현 명세](WorldGeneratorImplementationPlan.md)를 따른다.

## 확정된 결정

### 좌표계와 타일 데이터

- 월드는 유한하며 논리적인 `X/Z` 타일 좌표를 사용한다. 고도는 각 타일의 데이터로 저장한다.
- 타일 속성은 평탄한 1차원 SoA(속성별 배열) 구조로 저장한다.
- NPC는 연속적인 월드 좌표 위에서 이동하고, 지형 조회와 경로 탐색은 타일을 기준으로 처리한다.
- 청크는 처리와 렌더링을 위해 월드를 분할하는 단위다. 타일 데이터를 별도로 복제하거나 소유하지 않는다.

### 프로토타입 월드와 청크

- 프로토타입 월드 크기는 `512 x 512`타일이다.
- 청크 하나의 크기는 `64 x 64`타일이다.
- 전체 월드는 `8 x 8`, 총 64개 청크로 구성된다.
- 맵을 여러 플레이 공간으로 분리하지 않고 하나의 심리스한 논리 월드로 유지한다.

### 고도 체계

- 지형은 각 `X/Z` 타일에 지표면 고도 하나를 가지는 2.5D 높이맵으로 표현한다.
- 논리 고도 범위는 `-16 ~ +48`이며, 전역 해수면의 기준 고도는 `0`이다.
- 고도는 실제 미터가 아닌 논리 단위다. 렌더링 높이는 별도의 배율로 변환하며 초기 배율은 `0.25`로 둔다.
- 노이즈 생성 과정에서는 `float`을 사용하고, 확정된 타일 고도는 `short[] Elevation`에 정수로 저장한다.
- 지표면이 하나뿐인 높이맵에는 동굴이나 겹쳐진 지하 공간을 포함하지 않는다. 필요해지면 별도 레이어나 맵으로 설계한다.

### 물 판정

- 지표면 고도와 물의 존재는 서로 다른 데이터로 취급한다. 고도가 음수라는 이유만으로 물 타일이 되지는 않는다.
- `Elevation`은 땅의 높이를 뜻한다. 물 여부는 추후 추가할 수계 데이터로 판정한다.
- 전역 해수면 `0`은 바다 수면의 기준값일 뿐이며, 음수 고도의 마른 저지대도 존재할 수 있다.
- 바다는 해수면보다 낮으면서 외부 바다와 연결된 지형을 기준으로 생성하는 방향을 사용한다.
- 호수는 바다와 별개로 생성하며 전역 해수면과 다른 수면 높이를 가질 수 있다.

### 시드와 결정론

- 월드는 `ulong WorldSeed` 하나를 루트 시드로 사용한다.
- 사용자는 숫자나 문자열로 시드를 입력할 수 있다. 문자열은 실행 환경에 영향받지 않는 고정 해시 함수로 `ulong`에 변환하며 `string.GetHashCode()`는 사용하지 않는다.
- 지형, 온도, 습도, 수계, 식생, 동물 등 각 생성 시스템은 루트 시드에서 독립적인 하위 시드를 파생한다.
- 타일과 청크 단위의 임의성은 하위 시드와 월드 좌표를 함께 해시해 결정한다. 생성 순서에 의존하는 공용 전역 난수 생성기는 사용하지 않는다.
- 연속 노이즈는 청크 내부 좌표가 아닌 월드 좌표로 샘플링한다.
- 초기 결정론의 범위는 월드 생성으로 한정한다. NPC 시뮬레이션 전체의 결정론은 별도로 설계한다.
- 동일한 게임 빌드에서 `WorldSeed`, 생성기 버전, 생성 설정이 같으면 같은 초기 월드가 생성되어야 한다.
- 저장 게임에는 시드만이 아니라 생성된 월드와 플레이로 변경된 상태 자체를 저장한다. 시드, 생성기 버전, 생성 설정도 메타데이터로 보존한다.

### 노이즈 합성

- 지형의 기본 형태는 시드와 월드 좌표를 받는 2D 그라디언트 노이즈로 생성한다.
- 크기가 다른 노이즈를 fBm 방식으로 합성해 큰 지형 형태부터 작은 굴곡까지 만든다.
- 별도의 저주파 산악 마스크를 사용해 완만한 생활권과 험한 산악 지대를 구분한다.
- 산악 지대에는 약한 능선 노이즈를 추가할 수 있게 한다.
- 합성 결과에는 높이 분포 곡선을 적용한 뒤 논리 고도 `-16 ~ +48`의 정수로 변환한다.
- 맵에서 실제로 나온 최솟값과 최댓값으로 재정규화하지 않는다. 합성 진폭의 이론적 범위를 기준으로 정규화한다.
- 침식과 하천에 의한 지형 변화는 초기 노이즈 생성 범위에서 제외한다.

### 사용자용 지형 설정

- `GameWorldSettings`에서 사용자가 원하는 지형 성향을 선택할 수 있게 한다.
- 초기 선택지는 `평지형`, `균형형`, `산악형`의 세 가지 프리셋으로 둔다.
- 프리셋은 산악 지역 비율, 산악 강도, 기본 고도 진폭, 높이 분포 곡선 등 여러 내부 매개변수의 묶음이다.
- 사용자에게 옥타브, Lacunarity, Persistence 같은 저수준 노이즈 값을 직접 노출하지 않는다.
- 같은 시드라도 지형 프리셋이 다르면 다른 월드가 생성된다. 프리셋은 재현 조건인 생성 설정에 포함된다.

### 섬 마스크와 육지 형태 설정

- `GameWorldSettings`에서 육지의 전체 배치를 정하는 섬 모양 프리셋을 선택할 수 있게 한다.
- 초기 선택지는 `대륙형`, `군도형`, `판게아형`의 세 가지다.
- 대륙형은 서로 떨어진 여러 개의 큰 대륙, 군도형은 다수의 중소형 섬, 판게아형은 대부분의 육지가 연결된 하나의 거대한 대륙을 목표로 한다.
- 섬 모양은 육지의 연결과 바다 비율을 정하고, 지형 프리셋은 육지의 험준함을 정한다. 두 설정은 서로 독립적으로 조합할 수 있어야 한다.
- 맵 가장자리에는 바다 완충 구역을 두어 육지가 경계에서 잘린 것처럼 보이지 않게 한다.
- 섬 마스크와 해안선 변화는 월드 좌표 및 전용 하위 시드로 계산해 결정론을 유지한다.

### 디버그 렌더링

- 디버그 렌더러는 생성 데이터의 검사 도구이며 최종 게임 아트나 실제 게임 렌더러로 취급하지 않는다.
- 평면 `Texture2D`와 청크별 높이 메시를 함께 사용한다. 텍스처는 데이터를 색으로 표현하고, 높이 메시는 `Elevation`을 실제 Y축 굴곡으로 표현한다.
- 높이 메시는 `64 x 64`타일 청크별로 생성하며 타일마다 `GameObject`를 만들지 않는다.
- 디버그 텍스처는 고도, 기본 노이즈, 산악 마스크, 섬 마스크, 경사, 수계, 육지 연결 영역 등의 보기 모드를 제공할 수 있게 한다.
- 선택한 디버그 텍스처를 높이 메시 표면에도 표시해 Unity Scene 뷰에서 회전하며 데이터와 지형을 함께 검사할 수 있게 한다.
- 메시와 텍스처는 월드 생성 완료, 보기 모드 변경, 데이터 변경 시에만 갱신하며 매 프레임 재생성하지 않는다.
- 디버그 렌더러는 월드 데이터를 읽기만 하고 수정하지 않는다.
- 초기 범위에는 런타임 자유 카메라, 실시간 조명과 그림자, 지형 충돌체, LOD 및 수려한 물 표현을 포함하지 않는다. Unity Scene 뷰 조작으로 검사한다.
- 현재 프로젝트의 기본 렌더러는 URP 2D Renderer다. 높이 메시와 디버그 셰이더 호환성을 먼저 최소 장면에서 검증하고, 필요할 때만 Universal Renderer를 추가한다.

### 1차 프로토타입 완료 조건

- `GameWorldSettings`에서 시드, 월드와 청크 크기, 지형 성향, 육지 형태를 선택할 수 있다.
- `512 x 512` 월드를 `64 x 64` 청크 단위로 오류 없이 생성한다.
- 고도는 `-16 ~ +48` 범위를 지키며 청크 경계에서 끊기지 않는다.
- 초기 물 데이터는 `Dry`와 `Ocean`만 구분한다. 강과 호수는 후속 범위로 둔다.
- 동일한 시드, 생성기 버전, 생성 설정으로 다시 생성한 데이터의 체크섬이 일치한다.
- 지형 성향 3종과 육지 형태 3종의 9가지 조합을 모두 생성하고 차이를 확인할 수 있다.
- 청크별 높이 메시와 디버그 보기 모드로 Unity Scene 뷰에서 결과를 검사할 수 있다.
- 데이터 생성, 메시 생성, 육지 비율과 연결 영역 등 기본 통계를 확인할 수 있다.

### 1차 성능 목표

- 워밍업 이후 `512 x 512` 월드 데이터 생성은 1초 이내, 권장 목표는 500ms 이내다.
- 디버그 메시와 텍스처를 포함한 전체 생성은 2초 이내, 권장 목표는 1초 이내다.
- 생성 완료 후 디버그 화면은 최소 30 FPS, 권장 60 FPS를 유지한다.
- 생성 완료 후 월드 생성기와 디버그 렌더러의 프레임당 GC 할당은 0바이트를 목표로 한다.
- 월드 생성기와 디버그 렌더러의 추가 메모리는 128MB 이하, 권장 64MB 이하를 목표로 한다.
- 프로토타입 완료 기준은 `512 x 512`이며, `1024 x 1024`는 데이터 생성 스모크 테스트만 수행한다. 더 큰 맵은 후속 목표로 둔다.

### 1차 프로토타입 제외 범위

- 강, 호수, 강수, 침식
- 생태 군계, 식생, 동물
- NPC, 경로 탐색, 건축, 평탄화, 지형 수정
- 저장과 불러오기 및 정식 월드 설정 UI
- 최종 게임용 렌더링과 아트, 런타임 자유 카메라

## 잠정적 선택

- 월드와 청크 크기는 코드에 상수로 박지 않고 설정값으로 둔다.
- 초기에는 전체 월드 데이터를 메모리에 유지한다. 청크는 생성, 렌더링, 갱신 작업의 범위를 제한하는 데 사용한다.
- 기본 지형 노이즈는 파장 192타일, 4옥타브, Lacunarity `2.0`, Persistence `0.5`에서 튜닝을 시작한다.
- 섬 마스크는 큰 육지 형태, 해안선 굴곡 노이즈, 가장자리 감쇠를 합성하는 방식으로 구현한다.
- 디버그 높이 메시에는 하나의 공유 단순 머티리얼과 색상 텍스처를 사용하고, 충돌체와 그림자는 생성하지 않는다.

## 미결정 사항

- 프로토타입에서 임의 크기의 맵과 가장자리의 불완전한 청크까지 지원할지
- 원거리 청크의 활성화, 렌더링 및 시뮬레이션 규칙
- 프로토타입보다 큰 목표 맵과 스트레스 테스트용 맵의 크기
- 건축 시 요구할 지형 평탄도와 NPC의 평탄화 방식
- 각 지형 프리셋의 정확한 평야, 산악, 절벽 비율과 내부 매개변수
- 물 데이터를 `WaterDepth`, `WaterSurfaceElevation` 등 어떤 형태로 저장할지
- 하위 시드 파생과 문자열 변환에 사용할 구체적인 고정 해시 알고리즘
- 섬 모양별 목표 육지 비율, 주요 육지 개수, 연결성 기준 및 가장자리 바다 폭
- 디버그 보기 모드의 최종 목록과 타일 상세 검사 UI 범위
- 구체적인 자동 테스트 목록과 프리셋별 수치 기준
