# 월드 생성기 구현 명세

## 문서 상태

- 상태: 1차 구현 기준
- 기획 기준: [월드 생성](WorldGeneration.md)
- 목적: 현재 합의한 월드 생성기를 Unity에서 직접 조작할 수 있는 프로토타입으로 구현한다.
- 이 문서는 구현 순서와 역할을 정한다. 생성 결과의 미세한 수치는 실제 화면을 본 뒤 조정한다.

## 진행 상태

- 0단계 작업 상태 보호: 완료 (2026-10-18)
- 1단계 렌더러 최소 검증: 완료 (2026-10-18)
- 2단계 데이터, 좌표와 설정: 완료 (2026-10-18)
- 3~6단계: 대기

0단계 기준선:

- Unity `6000.3.22f1` 배치 모드에서 패키지 등록과 스크립트 컴파일이 종료 코드 0으로 완료됐다.
- 구현 코드는 아직 없으며 `main`과 `origin/main`의 커밋 기준선은 같다.
- 기존 작업은 한글 문서와 프로젝트 지침, Unity 6.3/URP 설정 자동 마이그레이션으로 구분된다.
- 자동 마이그레이션 파일은 `UniversalRP.asset`, `ShaderGraphSettings.asset`, `URPProjectSettings.asset`, `PackageManagerSettings.asset`이다. 구현 중 이 변경을 되돌리거나 덮어쓰지 않는다.

1단계 자동 검증 결과:

- 현재 URP 2D Renderer와 `Universal Render Pipeline/Unlit` 셰이더 조합에서 높이 메시가 카메라에 정상 렌더링됐다.
- 512 x 512 자동 캡처에서 배경과 다른 픽셀 23,436개를 확인했다.
- 별도의 Universal Renderer 추가는 현재 필요하지 않다.
- 사용자가 `RendererValidation` 씬의 Scene 뷰에서 메시가 정상적으로 솟아 있고 회전 표시되는 것을 확인했다.

2단계 검증 결과:

- `512 x 512`의 모든 타일 좌표를 1차원 인덱스로 변환한 뒤 다시 좌표로 복원하는 전수 검사가 통과했다.
- 모든 타일이 예상 청크 범위와 로컬 좌표로 왕복 변환되는 전수 검사가 통과했다.
- 설정 기본값, 유효하지 않은 크기와 시드, 청크 크기 불일치, 잘못된 높이 배율에 대한 테스트가 통과했다.
- `GameWorldData`의 SoA 배열 크기와 초기값 테스트가 통과했다.
- Unity Test Framework Edit Mode 결과: 총 21개 통과, 0개 실패, 0개 건너뜀.

## 구현 원칙

- 월드 데이터, 생성 로직, 디버그 렌더링을 분리한다.
- 생성 로직은 가능한 한 Unity 오브젝트에 의존하지 않는 일반 C# 코드로 작성한다.
- 초기 구현은 동기식 단일 스레드로 만든다. Jobs, Burst, ECS 및 외부 노이즈 패키지는 프로파일링 결과가 필요성을 보일 때만 검토한다.
- 타일마다 `GameObject`를 만들지 않는다.
- 생성 순서에 의존하는 전역 난수 생성기를 사용하지 않는다.
- Unity 씬과 에셋은 가능하면 Editor API로 생성하고 연결한다. YAML을 직접 작성하지 않는다.
- 기존 Unity 설정 변경과 사용자 작업을 보존한다. 커밋과 푸시는 사용자가 요청할 때 수행한다.

## 프로토타입 조작 흐름

1. `WorldGenerationPrototype` 씬을 연다.
2. Play를 누르면 기본 설정으로 월드가 생성된다.
3. Game 뷰의 간단한 디버그 패널에서 시드, 지형 성향, 육지 형태와 보기 모드를 바꾼다.
4. `재생성`을 누른다.
5. Game 뷰의 고정 카메라 또는 Play 중인 Scene 뷰에서 지형을 회전·확대해 확인한다.

정식 설정 UI와 런타임 자유 카메라는 만들지 않는다. 디버그 패널은 기능 확인을 위한 최소한의 IMGUI로 구현한다.

## 주요 데이터 구조

### 사용자 설정

`GameWorldSettings`는 `ScriptableObject` 에셋으로 만든다. 사용자에게 다음 값만 노출한다.

```text
SeedText           문자열 또는 숫자 시드
WorldWidth        기본 512
WorldLength       기본 512
ChunkSize         기본 64
TerrainPreset     Plains, Balanced, Mountainous
LandmassPreset    Continents, Archipelago, Pangaea
HeightScale       기본 0.25
```

`WorldHeight`라는 이름은 고도와 혼동될 수 있으므로 수평축 길이는 `WorldLength`로 부른다. 생성 시작 시 설정값을 검증하고 변경 불가능한 런타임 설정 스냅샷으로 복사한다.

검증 규칙은 다음과 같다.

- 너비, 길이, 청크 크기는 양수다.
- 프로토타입에서는 너비와 길이가 청크 크기로 나누어떨어져야 한다.
- 논리 고도와 해수면은 기획서의 고정값을 사용한다.

### 최종 월드 데이터

`GameWorldData`는 다음 데이터를 소유한다.

```text
Width, Length, ChunkSize
short[] Elevation
WaterType[] Water
```

초기 `WaterType`은 `Dry`, `Ocean`만 사용한다. 타일 인덱스는 `z * Width + x`로 계산한다.

청크는 별도 타일 배열을 소유하지 않는다. `ChunkLayout`과 `ChunkBounds`가 전역 배열에서 담당 범위만 계산한다.

### 생성 중 디버그 데이터

`WorldGenerationDebugData`는 최종 게임 데이터와 분리하며 다음 `float[]` 필드를 보관한다.

```text
BaseNoise
MountainMask
LandmassMask
Slope
```

디버그 렌더러가 필요 없는 실행 모드에서는 나중에 생성을 생략할 수 있게 한다.

### 생성 결과

`WorldGenerationResult`는 다음을 묶는다.

```text
GameWorldData
WorldGenerationDebugData
WorldGenerationStatistics
SettingsSnapshot
Checksum
GenerationTime
```

통계에는 최소한 육지와 바다 타일 수, 육지 비율, 연결 육지 수, 가장 큰 육지 비율, 고도 범위와 평균 경사를 포함한다.

## 시드와 노이즈 구현

### 고정 해시

- 문자열 시드는 UTF-8 바이트 기준 FNV-1a 64비트로 변환한다.
- 하위 시드와 좌표 해시는 SplitMix64 기반 혼합 함수를 사용한다.
- 지형, 산악 마스크, 육지 형태와 해안선은 고정된 서로 다른 도메인 ID를 사용한다.
- `string.GetHashCode()`와 `System.Random`을 월드 생성 결과에 사용하지 않는다.

### 노이즈

- 프로젝트 내부에 시드 기반 2D 그라디언트 노이즈를 구현한다.
- `FractalNoise2D`가 fBm 옥타브 합성을 담당한다.
- 모든 샘플은 전역 타일 좌표를 사용한다.
- 맵 안에서 관찰된 최솟값과 최댓값으로 결과를 재정규화하지 않는다.

초기 기본값은 파장 192타일, 4옥타브, Lacunarity `2.0`, Persistence `0.5`다. 정확한 값은 프리셋 비교 후 조정한다.

## 생성 파이프라인

`WorldGenerator`는 아래 단계를 순서대로 실행한다.

1. 설정 검증 및 시드 변환
2. 최종 데이터와 선택적 디버그 배열 할당
3. 기본 fBm 지형장 생성
4. 저주파 산악 마스크와 능선 성분 생성
5. 대륙형, 군도형 또는 판게아형 육지 마스크 생성
6. 육지 마스크와 지형 굴곡 합성
7. 높이 분포 변환, `-16 ~ +48` 범위 양자화
8. 맵 가장자리에서 4방향 flood fill을 수행해 `Ocean` 분류
9. 경사와 육지 연결 영역 및 통계 계산
10. 최종 배열 체크섬 계산

각 단계는 입력 배열을 명확히 받고 출력 배열을 채우는 독립 클래스로 나눈다. `WorldGenerator`는 순서만 조정한다.

### 프리셋 해석

- `TerrainPresetResolver`는 지형 성향을 고도 진폭, 산악 비율, 산악 강도와 높이 곡선으로 변환한다.
- `LandmassPresetResolver`는 육지 형태를 중심점 수, 크기, 연결 강도, 해안 굴곡과 가장자리 감쇠로 변환한다.
- 사용자 설정 에셋에는 저수준 노이즈 값을 노출하지 않는다.
- 같은 시드에서 평지형, 균형형, 산악형의 평균 경사가 순서대로 증가하도록 초기값을 잡는다.

## 바다와 연결 영역

- 해수면보다 낮은 타일은 물 후보일 뿐이다.
- 최외곽의 물 후보에서 시작해 상하좌우로 연결된 후보만 `Ocean`으로 분류한다.
- 외부 바다와 연결되지 않은 음수 고도는 `Dry`로 유지한다.
- 육지 연결 영역도 대각선을 제외한 상하좌우 기준으로 계산한다.
- 호수와 실제 수심 데이터는 1차 범위에서 제외한다.

## 디버그 렌더링

### 평면 텍스처

- 전체 월드에 `Texture2D` 한 장을 사용하고 타일 하나를 픽셀 하나로 표현한다.
- `Color32[]` 버퍼를 재사용하고 `SetPixelData`와 `Apply`는 보기 모드 변경 또는 재생성 시에만 호출한다.
- 초기 보기 모드는 `TerrainPreview`, `Elevation`, `MountainMask`, `LandmassMask`, `Slope`, `Water`, `LandRegions`로 한다.
- 청크 경계는 선택 가능한 오버레이로 표시한다.

### 높이 메시

- `64 x 64`타일 청크마다 메시 오브젝트 하나를 만든다.
- 청크 메시의 기본 격자는 `65 x 65` 정점과 `64 x 64` 쿼드다.
- 타일 중심 고도를 주변 타일과 평균해 격자 모서리 높이를 구한다. 월드 전역 데이터를 사용해 청크 경계의 양쪽이 같은 높이를 계산하도록 한다.
- 정점의 Y축은 `Elevation * HeightScale`로 계산한다.
- 전체 월드 기준 UV를 사용해 동일한 디버그 텍스처를 모든 청크 표면에 입힌다.
- 단순 공유 머티리얼 하나를 사용하고 충돌체, 그림자, LOD와 타일별 오브젝트는 만들지 않는다.
- 월드 재생성 시 기존 런타임 메시와 텍스처를 명시적으로 정리한다.

현재 URP 2D Renderer에서 최소 메시와 단순 셰이더를 먼저 시험한다. 필요한 경우에만 Universal Renderer Data를 추가하며 프로젝트 전체 렌더러 변경은 최소화한다.

## 프로토타입 씬

`Assets/GaemMeong/Scenes/WorldGenerationPrototype.unity`를 만든다.

씬에는 다음만 둔다.

- `WorldDebugController`
- 고정된 각도의 카메라
- 생성된 청크 메시의 부모 오브젝트
- 최소 디버그 패널

`WorldDebugController`는 설정 에셋의 런타임 복사본을 사용한다. Play 중 UI 조작이 원본 에셋을 변경하지 않게 한다.

에셋과 씬 생성 및 참조 연결은 일회성 Editor 도구로 수행하고 결과를 검증한다.

## 구현 단계와 역할

### 0단계: 작업 상태 보호

Codex:

- Git 상태와 기존 Unity 자동 변경을 확인하고 사용자 변경을 덮어쓰지 않는다.
- 구현 전 컴파일 기준 상태를 확인한다.

사용자:

- 기존 Unity 변경 중 의도적으로 유지하거나 제외할 항목이 있다면 알려준다.
- 별도 요청이 없으면 Codex가 기존 변경을 그대로 보존한 상태로 작업한다.

완료 확인:

- 구현 파일이 기존 변경과 분리되어 식별된다.

### 1단계: 렌더러 최소 검증

Codex:

- 삼각형 또는 작은 격자 메시와 단순 머티리얼을 생성한다.
- 현재 URP 2D Renderer에서 Scene 및 Game 뷰 표시 여부를 확인한다.
- 실패할 때만 Universal Renderer 추가안을 적용한다.

사용자:

- Unity에서 테스트 씬을 열고 메시가 보이는지 한 번 확인한다.
- 색상과 광택은 평가하지 않고 표시 여부와 카메라 각도만 확인한다.

완료 확인:

- 높이가 다른 단순 메시를 Scene 뷰에서 회전하며 볼 수 있다.

### 2단계: 데이터, 좌표와 설정

Codex:

- 어셈블리, 폴더, 좌표 변환, 청크 범위, 설정 검증과 데이터 배열을 구현한다.
- 기본 Edit Mode 테스트를 추가하고 실행한다.

사용자:

- 별도 조작 없음.

완료 확인:

- `512 x 512`, `64 x 64` 설정으로 모든 인덱스와 청크 범위가 유효하다.

### 3단계: 시드와 기본 지형

Codex:

- 고정 해시, 하위 시드, 그라디언트 노이즈, fBm과 고도 양자화를 구현한다.
- 동일 시드 재현성과 청크 경계 연속성을 검사한다.
- 평면 고도 텍스처를 먼저 출력한다.

사용자:

- 고도 지도가 지나치게 잘게 끊기거나 한 방향으로 치우쳐 보이는지 확인한다.

완료 확인:

- 동일 설정 체크섬이 반복 생성에서 일치하고 고도 범위를 벗어나지 않는다.

### 4단계: 지형과 육지 프리셋

Codex:

- 평지형, 균형형, 산악형을 구현한다.
- 대륙형, 군도형, 판게아형 마스크와 가장자리 감쇠를 구현한다.
- 바다 flood fill과 연결 영역 통계를 구현한다.

사용자:

- 9가지 조합 중 대표 조합을 보고 프리셋 이름과 결과가 직관적으로 맞는지 평가한다.
- 평야가 너무 적거나 산이 과도한 경우 선호 방향을 알려준다.

완료 확인:

- 9가지 조합이 오류 없이 생성되고 서로 구분된다.

### 5단계: 높이 메시와 디버그 도구

Codex:

- 청크별 높이 메시, 디버그 텍스처 보기 모드, 통계와 최소 조작 패널을 구현한다.
- 프로토타입 씬과 설정 및 머티리얼 에셋을 생성하고 연결한다.
- 재생성 시 런타임 리소스가 누적되지 않는지 확인한다.

사용자:

- Play 후 시드와 프리셋을 바꾸고 재생성해본다.
- Scene 뷰에서 지형을 회전하며 높이 배율과 지형의 완만함을 평가한다.

완료 확인:

- 코드나 씬 배선 수정 없이 Unity UI와 Scene 뷰만으로 프로토타입을 조작할 수 있다.

### 6단계: 1차 검증과 튜닝

Codex:

- 컴파일, 기본 테스트, 재현성, 오류 로그와 성능 측정을 수행한다.
- 합의된 1차 성능 기준과 알려진 한계를 문서에 기록한다.
- 사용자 피드백에 따라 프리셋의 내부 수치를 1차 조정한다.

사용자:

- 최종 후보 시드 몇 개를 둘러보고 다음 개발 단계로 사용할 만한 도화지인지 판단한다.
- 가능하면 실제 목표 노트북에서 프레임 속도와 생성 체감을 확인한다.

완료 확인:

- [월드 생성](WorldGeneration.md)의 1차 프로토타입 완료 조건을 충족한다.

## 검증 전략

구체적인 테스트 수와 프리셋 합격 수치는 구현 결과를 본 뒤 확정한다. 첫 구현에서는 다음만 필수로 검증한다.

- 좌표와 인덱스 및 청크 경계
- 잘못된 설정 거부
- 고도 범위
- 동일 설정의 체크섬 재현
- 다른 시드 또는 프리셋의 결과 차이
- 최외곽 바다와 flood fill
- 9가지 프리셋 조합 생성
- 재생성 후 오류와 런타임 리소스 누적 여부

테스트는 설치되어 있는 Unity Test Framework의 Edit Mode 테스트를 우선 사용한다. 시각적 품질은 자동 테스트로 단정하지 않고 사용자가 직접 확인한다.

## 구현 중 사용자 확인이 필요한 시점

다음 세 시점 외에는 Codex가 합리적인 구현 세부사항을 결정하고 계속 진행한다.

1. 현재 URP 2D Renderer에서 높이 메시가 정상 표시되는지 최초 확인
2. 지형 및 육지 프리셋의 시각적 방향 확인
3. 1차 프로토타입 완료 후 높이 배율과 전체 사용감 확인

렌더러 교체처럼 프로젝트 전체 표현 방식에 영향을 줄 수 있는 변경이 필요하면 적용 전에 이유와 범위를 알린다.

## 예상 일정

- 처음 조작 가능한 러프 버전: 약 6~10시간
- 완료 조건을 충족하는 1차 프로토타입: 약 15~30시간
- 하루 1~2시간 취미 개발 기준: 약 1~3주

절차 생성 수치의 미세 조정과 최종 아트 작업은 이 예상에서 제외한다.
